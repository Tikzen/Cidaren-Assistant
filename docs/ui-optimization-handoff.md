## 建议优化方向

以下是设计方向，不规定具体控件组织形式：

- 减少按钮、提示文字和边框在同一区域内争夺注意力，突出当前账号、正在执行项和下一步操作。
- 登录前、登录后无任务、队列为空、任务选中、运行中、暂停、失败、结束等状态都应有清楚反馈。
- 主操作与辅助操作层级清楚，避免误以为「开始任务」可以绕过队列。
- 长任务名可阅读，窗口缩放后不挤压关键操作；任务表和队列都能容纳较多项目。
- 可考虑任务搜索、选择数量、状态筛选及适度的右键操作，但不能悄悄改变「一键添加全部」的范围。若新增筛选，需明确按钮添加当前可见任务还是当前类别全部任务。
- 队列卡片应能看懂任务名称、执行方式、状态、当前进度及停止原因；拖动和多选排序保持直观。
- 明暗主题中的正文、占位文字、选中态、禁用态和状态色均需检查；颜色不应是状态的唯一表达方式。
- 日志保留导出和自动滚动控制，不应挤占主要任务区域。
- 首选项优先使用可适应字号、留有解释空间的布局，区分实际等待时间和服务端上报用时。
- 保留 macOS 原生窗口按钮、菜单和常用快捷键习惯；多开入口需要容易发现。
- 不在产品主流程展示内部技术实现、测试编号或历史性能实验。

## 必须保留的任务行为

### 所有执行都经过队列

保留原有功能入口，去掉的「一键刷题」不要恢复为绕过队列的独立执行路径。

- 「加入队列」支持多选任务。
- 「一键添加全部」当前实现添加当前任务类别列表的全部项目。
- 支持拖动等待项排序，上移、下移等替代操作可保留。
- 正在执行的项目不允许拖动、删除或改变执行方式。
- 「开始任务」先把所选任务加入队尾，再按已有队列顺序执行。
- 「一键满分」也先加入已有队尾，不能插队直接执行。
- 同账号、同任务、同模式的等待或运行项去重；不同模式可以混合排队。

### 三种执行方式

| 方式 | 已确定的含义 |
| --- | --- |
| 从头开始 | 显式重新完整选词。已有进行中的小节时，先续完小节，再重新完整选词；服务端不支持时说明并跳过。 |
| 重做提分 | **只有完成度达到 100% 的学习任务可以勾选。** 只处理错词、未满分词，不重新执行整个任务；需要服务端支持重做和自选单词。 |
| 一键满分 | 完成度 100%：直接提分；未完成：先续做当前刷题流程，再运行有界提分流程。不要恢复成续完后又重新全选的重复刷题行为。 |

**完成度 100% 与成绩 100 分不是一个字段。** 完成度 100%、成绩不足 100 的学习任务正是提分功能的主要对象。已经满分且没有未满分词的任务应直接完成，不强行重做。

任务列表和队列内的提分勾选均限制为已完成学习任务。测试任务不支持提分。已完成的测试任务不能强行重启。

「一键满分」旁保留圆圈感叹号，鼠标悬浮显示说明。当前公共文案：

> 仅支持可重做并自选单词的任务。完成度已达 100% 时直接重做提分；未完成时先刷题，再自动运行一次“重做提分”流程。耗时显著增加，仅推荐有成绩要求的任务使用。

提分说明需要表达：只重做错词、未满分词，只支持可重做且允许自选单词的任务。可润色表达，不改变含义。

### 重试、跳过与停止

UI 必须区分普通跳过、失败、已取消、待核对提交、待安全验证、刷题完成但提分跳过等结果。

- 不支持重做、不能选词或提分无进展：说明原因并继续下一项。
- 请求最多尝试 5 次，原地重试，不自动从头重跑整个任务。
- 写请求结果不明：标记待核对，不自动重发原请求；继续其他项。
- 提分最多 10 轮、30 分钟，连续两轮分数无提升即停止。不要通过 UI 重试逻辑绕过这些限制。
- 安全验证或账号失效：停止本轮请求，保留等待项。
- 用户主动暂停保留当前执行位置；恢复不重新开始任务。用户手动暂停时间不计入用时额度。
- 异常退出后保留队列和顺序，中断项待核对，不自动重复执行。
- 失败历史不等于当前服务端成绩；刷新任务列表应读取当前成绩，不伪造历史结果。

## Token、多开与共享数据

- 业务会话创建时即直连，获取 Token 不自动暂停队列。
- 当前窗口运行时获取新 Token，只填入输入框，不能替换正在运行的账号或会话。
- 通过「新开窗口 / 多开」打开独立进程，不同账号可并行运行。
- 同账号正在其他窗口运行时，本窗口只能查看，不重复启动。
- 答案库、错题记忆、词表池和查词缓存在窗口之间共用，不按账号隔离。
- 不改动现有 Token 捕获的代理、证书、清理逻辑；本轮 UI 验证不启动真实捕获、不改系统代理。
- UI 样式验证使用示例数据，截图隐藏 Token、账号身份及其他个人信息。
- 用户明确要求不要操作其他正在运行的账号。不得为了 UI 测试重新登录、重新刷题、重置真实任务或终止现有进程。
