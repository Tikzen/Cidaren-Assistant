# 修复未初始化任务及队列中的旧任务 ID

## 原因

Windows 日志中四个班级学习任务初始 `task_id=-1`。平台后来分配了有效班级任务 ID，但队列刷新按 `task_id + release_id` 查找，找不到后回退到旧快照，重复提交旧 ID。

同时，旧流程通过 `StudyTask/Info` 读取课程自学实例。该实例 ID 与同单元班级发布任务的 ID 不同，不能用于班级选词提交。

失败出现在 `ClassTask/SubmitChoseWord`，平台返回「对不起，加载任务信息失败，请返回首页重新加载」。收到错误响应，说明已运行到业务接口调用阶段。

## 修复

- 以课程、发布 ID 和任务类型重新关联最新任务，必要时以任务名称消歧；不以变化中的执行实例 ID 作为关联前提。
- 班级学习任务按官方页面流程读取 `ClassTask/Info(task_id, release_id)`，使用响应中的有效 ID 和词表，不混用课程自学实例。
- 初始化得到的新 ID 会写回队列，即使后续执行失败也保留；原失败项可直接手动重试，无需删除后重新加入。
- 队列去重和界面完成状态关联不再因 `-1` 变为正数而失效。
- 没有有效 ID 时禁止提交选词；任务已经移除、过期或匹配有歧义时，不继续使用旧快照执行。
- 初始化接口响应中断时标记提交待核对，不盲目重放可能创建任务的请求。
- 补充修复回归中发现的多进程日志清理竞态：另一进程删除日志后，当前进程不再因读取修改时间失败而退出。

## 验证

162 项离线测试通过，新增覆盖：占位与已变化 ID 的重新关联、旧失败队列持久化后重试、ID 变化后的去重、课程和任务类型隔离、首次初始化的新 ID、编码响应、无效初始化阻止选词、初始化后的 ID 保存、初始化结果不明时不自动重放，以及并发清理日志。

验证未使用日志内账号或 Token，未调用真实答题或初始化接口。Windows 可执行程序需要用包含该修复的源码重新构建后，安装版才会生效。
