# U5 / U6 单词卡片错误修复

## 原因

新世纪3 U6 Text A 在英译汉题中出现 `satisfied`，单元词表使用 `satisfy`；U5 Text A 对应的是 `hung` 与 `hang`。孤立单词的模型词形还原未得到词表中的原型，旧逻辑继续用题干词形请求单元卡片，服务端返回 `code=120`（卡片数据错误，请切换其他卡片学习）。错误被当作整项业务失败，重复启动会在同一词形再次失败。

此前明确原型核对只覆盖重做流程，普通刷题未使用这一回退。

## 修改

- 普通英译汉题在本地词表及模型均无法确定原型时，沿用已有 `SearchWord` 原型核对接口。
- 仅接受当前单元词表中的原型；无法确认时不请求无效单词卡片，按已有兼容策略处理当前题。
- 同一任务、课程、单元下缓存已核对的词形，减少重复查询。
- 仅将查词接口的 `code=120` 转为当前题的数据缺失；登录失效、安全验证和其他业务拒绝仍按原有机制上抛。
- 一键满分对未完成任务先续做当前刷题流程；仅明确选择“从头开始”时重新完整选词，避免续完小节后再次刷全词。
- 保留原请求尝试上限、提分轮次上限与连续无进展停止条件。

## 在线续跑发现的其他问题

- 词语搭配题（mode 31）用查询优先级排序后的选项下标提交，和服务端原始选项顺序不一致。改为使用原始选项下标。
- 服务端会在连字符空位之间插入空格，例如 `_  _-  _  _`。空位解析先统一这些空白，保留连字符的两个词位。
- “排放管制”在当前单元词典和共享答案库中缺少完整短语。根据题干和选项人工核对 `emission controls`，作为候选补入现有共享答案库，交由服务端实际判分验证；没有伪造服务端标准答案或绕过停止上限。运行数据不纳入源代码提交。

## 离线验证

149 项测试通过，其中词形回归覆盖：`satisfied → satisfy`、`hung → hang` 的词表核对与重复查询复用；无结果、其他单元原型不查询卡片；查词卡片错误与登录失效、安全验证的区别；当前题的数据缺失不会直接结束整个任务。

在线续跑另外发现 U5 的“追寻梦想”短语位于词典 `usage.eg`，缺少中文字段，原流程漏读。新增保守回退：只有例子全部词位被当前选项及空位完整覆盖、且结果唯一时才使用；有未匹配词、多个候选或中文含义不一致时不采用。新增三项回归覆盖这些边界。

命令：`.venv/bin/python -m unittest discover -s tests`。

在线验收只处理用户指定的 U5 Text A、U6 Text A，使用账号执行锁避免同账号任务并行；原始运行记录保存在 Git 私有目录，不提交 Token 或账号响应。最终已通过新会话重新读取任务列表和各任务单词状态核对。
